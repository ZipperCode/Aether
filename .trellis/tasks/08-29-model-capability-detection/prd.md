# 模型能力检测与官方对照

## Goal

在提供商模型的现有联通测试旁新增一键“模型能力检测”，用可自动判分的随机客观题快速发现明显能力降级；可选地与用户指定的可信官方直连模型在同题、同参数下比较，减少手工复制题目和逐个测试的工作。

## Background

- 现有模型测试验证协议、鉴权、候选与延迟，但不提供能力评分。
- 黑盒输出无法证明底层模型身份；产品只能报告能力或行为偏离，不能宣称“确认真模型”或“确认掺水”。
- 用户已确认首版采用双层检测、运行时随机客观题、40 题快筛加 100 题复核、中文/英文/双语可选且默认双语、首次选择可信官方参考后保存复用。

## Requirements

1. 在每个可进行文本生成的提供商模型行增加独立的能力检测入口，不改变现有联通测试行为。
2. 提供 `quick` 40 题和 `verify` 100 题两种模式；快筛异常只建议复核，复核才允许报告明显能力偏离。
3. 支持中文、英文、双语三种语言配置，双语为默认；不同语言配置的结果不得互相比较。
4. 题目必须由服务端按版本和随机种子生成，覆盖数量、逻辑、算法、语言关系和指令遵循五个等权维度；每题有唯一、可程序判定答案。
5. 不使用运行时 LLM 出题、LLM 裁判或打包固定公开题库；浏览器不得在运行前拿到题目或答案。
6. 每次运行固定目标 endpoint 和 Key；官方参考也固定 endpoint 和 Key。运行过程中禁止跨候选或跨 Key failover。
7. 没有官方参考时只展示能力画像；启用官方参考时，目标与参考必须接收完全相同的题目和测试条件。
8. 首次从 Aether 已有 provider、模型、endpoint、Key 中选择可信官方参考，并保存为目标模型配置；引用失效时要求重新选择，不能自动换参考。
9. 结果必须展示五维分数、总体分、95% 置信区间、覆盖率、耗时、可取得的 token/费用和失败分类。
10. 结论固定为能力画像、未发现明显偏离、建议复核、复核未发现显著偏离、与参考明显不一致、无法判断；所有页面明确说明这不是模型身份认证。
11. 网络失败、限流、超时、过滤、截断和无法解析必须单独分类。覆盖不足或配置不一致时返回无法判断，不能计为能力下降。
12. 沿用管理端 provider-query 写权限；不得在日志或响应中暴露密钥、完整请求头、完整上游响应体或模型推理内容。
13. 首版使用有界同步请求和取消，不新增数据库迁移、通用后台任务系统或运行历史。

## Acceptance Criteria

- [x] 文本模型行显示能力检测入口；非文本格式或无可用 endpoint/Key 时禁用并解释原因。
- [x] 40/100 题数量、五维配额和中文/英文/双语配额由测试证明正确且同种子可复现。
- [x] 目标和参考使用同一题集并分别固定到一个明确 endpoint/Key；运行中没有 failover。
- [x] 未配置参考时返回能力画像；首次保存后后续运行可复用，引用失效时安全失败。
- [x] 快筛覆盖率至少 90%，分差至少 15 个百分点且单侧 McNemar `p < 0.05` 才建议复核。
- [x] 复核覆盖率至少 95%，分差至少 10 个百分点且 `p < 0.01` 才报告与参考明显不一致。
- [x] 结果包含分维度评分、总体评分、Wilson 区间、覆盖率、失败分类、耗时及可用的 usage/cost。
- [x] 取消、总超时、限流、拒答、无法解析和覆盖不足均得到明确且不误导的结果。
- [x] 路由权限、响应脱敏以及 OpenAI Chat/Responses、Claude Messages、Gemini GenerateContent 的文本响应路径有范围化验证。
- [x] 前端类型检查、后端范围化测试、格式检查和 diff 检查通过。

## Out of Scope

- 公开排行榜或与公开 benchmark 榜单直接换算。
- EvalScope、lm-evaluation-harness 或其他 Python/Node runner 依赖。
- 模型指纹、硬件证明、定时监控、自动停用/切路由、运行历史、趋势和报告导出。
- 图片、音频、视频、embedding、rerank、realtime、files 等非文本生成能力。
