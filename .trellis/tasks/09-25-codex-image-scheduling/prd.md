# Codex OAuth GPT Image 调度修复

## 需求

Codex OAuth 上游模型发现可能不返回 `gpt-image-2`，但账户实际可生图。管理员配置生图模型后，不应仅因发现列表缺少该模型而在本地调度阶段报 Key 不支持模型。需要检查生图 Endpoint、模型配置和执行链路，使 GPT Image 能走正常调度并执行。

## 验收标准

- 对照 sub2api 或 codexProxy 的公开实现，以源码证据解释生图路由及调度方式。
- 当 Codex OAuth 发现列表仅含文本模型时，已正确配置的 GPT Image 生图请求可选中合格 Key 并进入正确上游执行路径。
- 保留用户显式模型限制、Endpoint 绑定、鉴权、健康、额度及非 Codex 模型支持检查，不全局绕过调度。
- 新鲜发现数据和现存缺少生图模型的发现缓存均有明确处理方式。
- 运行覆盖真实网关请求与本机上游响应的验证及相关回归检查；未使用真实账户时明确不能证明真实上游账号权限。
- 更新现有相关文档，说明配置方式与行为边界。

## 约束

不修改本次任务前已有未提交改动，不进行 Git 写操作、依赖安装、远端写入或凭据访问。研究时区分 Codex OAuth 和 ChatGPT Web 生图，不混用协议。
