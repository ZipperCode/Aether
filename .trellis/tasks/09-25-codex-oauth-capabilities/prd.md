# 完善 Codex OAuth 套餐能力与图片搜索链路

## 目标

完整检查并修复现有 Codex OAuth 模板暴露的 Endpoint，使图片、OpenAI Search 及其他已声明接口按照实际账号能力正常发现、调度、测试和转发，保留已工作的 Responses 行为。

## 背景与已确认事实

- 用户明确授权本地实现和验证；生产变更、推送和发布不在当前授权范围。
- 154 服务器 v0.7.38 的 4 个 Pro 账号在图片测试中均被 `key_model_not_allowed` 拦截；自动发现仅包含文本模型。两个 Pro 的额度快照已耗尽，账号套餐、模型准入和实时额度是不同条件。
- 当前代码只补全 `gpt-image-2`，不能覆盖管理员已经配置的 `gpt-image-2.5-flare`、`gpt-image-2.5-sunburst` 或后续同协议型号。
- 用户同时报告 OpenAI Search 不可用，要求完善所有 Codex OAuth 已暴露能力；需以源码、线上只读记录和本机真实 HTTP 测试确定缺陷。

## 要求

1. 图片能力来源复用启用的模型配置与 Endpoint 绑定，避免固定版本名单；自动发现刷新不丢失已配置的新图片模型。
2. 根据官方当前说明阻止 Free Codex 生图，区分 Plus、Pro、ProLite 和未知套餐；套餐不等于所有型号的授权。Search 根据已配置的原生 Endpoint 和真实发现的模型形成可尝试路由；`supports_search_tool` 是工具发现能力，不能作为 Alpha Search 权限。没有可靠证据时不凭套餐名称虚构额外权限；明确限制、模型/格式白名单、健康及额度均须保留。
3. 修复 OpenAI Search 的发现、模型绑定、候选筛选、请求构造、管理测试和正式执行之间的断点；不将 Search 偷换成 Responses 文本生成。
4. 审计 Codex 模板中的其他已声明 Endpoint，并修复同源缺陷；真实不支持的能力明确诊断，不伪造成功。
5. 新鲜发现、旧缓存、自动白名单更新、人工限制及可用性协调保持一致，原生 Codex 模型目录保持原样。

## 验收

- 使用未硬编码的未来图片模型名称仍能通过已配置的图片 Endpoint 进入真实本机上游；显式限制及无 Endpoint 的情况不得被放开。
- Search 测试与正式调用选中正确模型和 Endpoint，保留请求/响应协议；提供覆盖真实 HTTP 的回归。
- 有针对套餐/权限、额度耗尽和未知套餐的明确回归；不同原因的诊断不会混为“不支持模型”。
- 对其他 Codex 模板接口给出逐项验证结果，Responses/Compact 等相关回归通过。
- 相关测试、规格文档和中文本地提交完成；不声称本机 mock 验证等于真实账号上游验收。

## 边界

不改生产配置、不写生产数据库或 Redis、不触发真实付费生成、不推送或发布；不引入隐式协议回退、宽泛模型前缀授权或凭空的套餐支持矩阵。
