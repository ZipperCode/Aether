# 技术设计

## 集成边界

任务分支 `codex/sync-upstream-20260823` 从本地 `master` 基线创建。先合并 `origin/master`，再合并 `upstream/main`；主工作区在验证完成前不接收任何任务提交。

## 冲突策略

1. 无冲突文件直接保留 Git 的三方合并结果。
2. 本地已重构的文件以当前本地架构和契约为骨架，逐项移植上游行为，不整文件选择任一侧。
3. 上游新增的安全校验、协议兼容、数据迁移和公开接口行为不得因本地重构被静默丢弃。
4. 本地独有的 Endpoint 推断、Responses 错误提交修复及任务后续提交不得回退。
5. 手工新增或改写的业务逻辑遵循项目中文说明要求；不改第三方、生成物和纯上游无冲突内容。

## 提交与回滚

- 两次合并分别形成提交，便于定位 origin 同步与源仓库同步。
- 任一阶段失败时仅丢弃隔离 worktree/任务分支，主工作区仍停留在原始基线。
- 完成验证后在主工作区执行 fast-forward 合并；若用户修改与任务提交重叠，停止并报告，不 stash、不覆盖。

## 验证

- Git：祖先关系、未合并条目、工作区状态、`git diff --check`。
- Rust：`cargo fmt --all --check` 与 `cargo check --workspace`。
- Frontend：`npm run type-check`；不执行会自动修复文件的 lint。
- 仅在上述检查暴露具体失败时补跑对应最小测试，不默认运行全量测试。
